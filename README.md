# Система оплаты интернет-магазина

Учебный проект Родионовой Марии Сергеевны, группа 15.22Д-ПИ01/26м.
Практические работы 2 и 4, вариант 7.

Модуль payment.py рассчитывает стоимость заказа и моделирует оплату через
тестовый платёжный шлюз. Реальные банковские операции не выполняются.
Для работы достаточно Python 3.12 и стандартной библиотеки.

## Локальный запуск проверок

    python -m compileall -q payment.py tests scripts
    python -m unittest discover -s tests -v
    python scripts/build_docs.py
    python scripts/package_release.py

Документация создаётся в build/docs/index.html, архив — в dist/.
Файлы из build/ и dist/ не включаются в историю Git: их собирает CI из исходников.

## Проверки в GitHub Actions

Файл .github/workflows/main.yml задаёт workflow Payment CI.
Он запускается при push в любую ветку и при публикации любого тега,
при открытии или обновлении Pull Request и вручную через workflow_dispatch.
Сначала проверяется синтаксис, затем запускаются тесты, создаются HTML-страница
с API и архив версии. Артефакт хранится 14 дней. Ошибка любой стадии останавливает
следующие стадии. Установка сторонних Python-пакетов не требуется.

## Разработка и выпуск

Новые изменения выполняются в development. После успешных тестов создаётся
Pull Request development → main. Для выпуска используется release: в ней
обновляется VERSION и документация. После проверки и слияния создаётся
аннотированный тег v1.0.0; его push запускает тот же workflow и сборку артефакта.

## Автоматическое слияние на GitHub

Администратор репозитория должен включить Settings → General → Allow auto-merge.
Для main необходимо правило ветки с обязательной проверкой Tests and package,
которую публикует Payment CI. Имя следует выбрать из списка после первого запуска.
В правило также включается Require a pull request before merging.

Для собственного Pull Request включается Enable auto-merge с методом Squash.
То же действие при наличии авторизации GitHub CLI:

    gh pr merge <номер_PR> --auto --squash --match-head-commit <полный_SHA>

Команда связывает решение с конкретной вершиной Pull Request. GitHub выполнит
слияние, когда будут соблюдены обязательные проверки и остальные правила ветки.
Не следует отключать обязательные проверки для получения зелёного статуса.

Создание Pull Request, включение правил ветки и наблюдение за статусом Actions
требуют доступа к GitHub. Локальный запуск тех же команд проверяет код и сборку,
но не подтверждает выполнение на сервере GitHub.
